# Revisión reproducible de BML

Repositorio: `SugarFreeDoNoSo/bml`.
Commit revisado: `626f12f2d4a55817a31ec66562dff0eb3f81a2fa`.
Esta revisión distingue código observado, contratos comprobados y objetivos futuros.

## Hallazgos funcionales prioritarios

El comando `cargo run -p bml-tests --example contract_audit --locked` ejecuta
fixtures pequeñas y compara contra valores independientes. En la versión revisada
produce seis discrepancias y un control correcto; termina con código 1.

| Prioridad | Contrato / caso mínimo | Resultado observado | Causa localizada |
|---|---|---|---|
| P0 | `Op(Op(x,y),x)` con `x=1,y=4` debe dar `1` | `inf` | `compiler/src/rpn.rs::emit` sustituye cualquier nodo visitado por `Dup`, aunque su valor ya no esté en el tope |
| P0 | Constante plegada `Op(1,1)` debe dar `2` | `NaN` sin pool; `2` con pool | Los builders de tests/bench usan `into_soa()` y `evaluate()` sin conservar el pool |
| P0 | Producto positivo `0.5 * 2` debe dar `1` | `NaN` | `domain/src/transformer.rs::mul` usa `add(log2(x),log2(y))`, pero `add` requiere primer argumento positivo |
| P0 | GGUF F32 con alignment 64 y pesos `[1,2]` | `[0,0]` | `parser/src/gguf.rs::open` fija alignment 32 e interpreta padding como datos |
| P0 | Orden Q4_0: 16 nibbles bajos y luego 16 altos | Valores bajos/altos intercalados | `compiler/src/gguf_compiler.rs::dequantize_q4_0` hace dos `push` por byte |
| P0 | Bloque Q4_0 de 17 bytes debe rechazarse | Se acepta y rellena con ceros | El decoder interrumpe la lectura y completa valores faltantes |

El ejemplo de diagnóstico es código nuevo; no corrige esas implementaciones.
Cada fallo tiene una tarea de migración y debe convertirse en regresión del crate
propietario al repararse. El test del pool demuestra una pérdida de contexto en
los consumidores; no exige que un programa RPN sin pool invente sus constantes.

El formato Q4_0 se contrastó con
[`dequantize_row_q4_0` de GGML](https://github.com/ggml-org/ggml/blob/master/src/ggml-quants.c).
El blob consultado fue `1ebc50a763f16db909de37090da38cc8c0fdde94`.
La regla de alignment está en la
[especificación GGUF](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md).

El workspace ya registra las seis suites de `tests/` mediante `[[test]]` en
`crates/tests/Cargo.toml`. El problema principal es el oráculo y el alcance del
contrato, no que Cargo ignore esas carpetas.

## Alcance y rendimiento

- `compiler` contiene lectura/dequantización, funciones numéricas, tokenizer,
  sampler, KV cache, distribución e inferencia: esas responsabilidades exceden
  la compilación y deben migrar a capas distintas.
- `bml_dot_program` usa `FMul` y `FAdd`. El nombre BML identifica el proyecto,
  pero no demuestra ejecución exclusiva mediante la primitiva BML.
- `bml_swiglu_program` omite sigmoid y reduce a una suma de productos;
  `bml_rmsnorm_program` retorna una reducción y no el vector RMSNorm completo.
  Necesitan contratos de salida antes de usarse como kernels equivalentes.
- `crates/bench/src/main.rs` divide un conteo nominal de operaciones por una
  estimación de operaciones/token. No ejecuta el modelo. Además, el builder
  pierde el pool y la cadena se vuelve no finita. La comparación histórica con
  `llama-bench` no acredita throughput equivalente ni calidad.
- `compiler/benches/fma_vs_bml.rs::fma_repeated` calcula exponenciales y
  logaritmos, no una FMA `a*b+c`; su etiqueta induce una comparación incorrecta.
- `BmlWeightPool::estimated_size_bytes` estima bit-packing. No mide la memoria
  real de los `NodeId`, nodos y pools ni un archivo serializado. Q4_0 incorpora
  escalas por bloque: no implica solo 16 pesos dequantizados únicos en todo el modelo.
- El tamaño del bytecode es tráfico de datos; no mide directamente el tamaño
  de instrucciones del intérprete en L1i. `repr(align(64))` sobre una estructura
  con `Vec` tampoco alinea automáticamente sus buffers de heap.

## Estado de verificación

Entorno de revisión: Linux x86_64, Rust 1.98.1, Cargo con `--locked`.

- `cargo test -p bml-domain --locked`: 39 unitarios existentes, 15 tests nuevos
  de `symbolic_contracts` y un doctest nuevo pasan (55 en total).
- El diagnóstico nuevo reproduce las seis discrepancias anteriores.
- `cargo test --workspace --locked` falla en `strace_shows_mmap_not_read` porque
  el entorno no permite `ptrace`; no es evidencia de un fallo matemático.
- La ejecución con `--no-fail-fast -- --skip strace_shows_mmap_not_read` alcanza
  las demás suites y encuentra un doctest anterior en `runtime/src/scheduler.rs`:
  un bloque de texto sin etiqueta se intenta compilar como Rust.
- La propuesta OpenSpec pasa validación con versión 1.13.1. La revisión automática
  bloqueó el primer intento por una conexión externa; la validación final usó
  las opciones documentadas `OPENSPEC_TELEMETRY=0`, `DO_NOT_TRACK=1` y
  `OPENSPEC_NO_UPDATE_CHECK=1`, tras verificar su implementación.

No se declara que toda la suite esté verde, ni se elevan las tareas históricas
marcadas como completas a evidencia de corrección. El detalle final de validación
de esta rama queda registrado en el pull request y en las tareas OpenSpec.
